Rules for builders

  • Colour. Teal is structure and the one action colour. Gold marks a point, a rule or a focus ring; it is never text and never a fill larger than a dot. Status colours appear only on status.
  • Local and cloud. A filled teal dot means "on this machine", a hollow slate ring means "cloud". Use the pair everywhere a model is named; never colour alone, always with the word on first use in a view.
  • Numbers. Money, time, tokens and ids use the mono face with tabular figures. Money shows three decimals under one dollar, two above. An estimate always carries the word "Estimate".
  • Words. Say what happened in a sentence ("200 emails went to local-small"), not field names. Raw records sit behind a "Details" control. Errors say what failed and what to do next.
  • Layout. Spacing only from the scale (4, 8, 12, 16, 24, 32). One card style. Page gutter 24px, 16px on phones. Nothing scrolls sideways except a table or the plan inside its own box.
  • Type. 15px body, 13px secondary, 12px labels in capitals with letter spacing, 22px page title, 16px card title. System fonts only: the app must work with no internet.
  • Plan diagram. Plain SVG. Columns by dependency depth, left to right. Plan and Compose use the soft teal fill. An apply_to_each step is one node with its item count. The selected node has a 2px teal border.
  • Themes. Light by default; dark follows the system or the switch (data-theme on the root). Every colour comes from a token.
  • Replay. In replay mode the amber chip in the top bar is always visible and the Ask box is replaced by buttons for the recorded jobs.
